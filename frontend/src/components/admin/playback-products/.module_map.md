# frontend/src/components/admin/playback-products/.module_map.md

## Components

- `PlaybackProductCard.jsx`: One package — reads price/depth/validity at a glance, toggles whether it
  is sold, and edits its commercials in place. Owns its own edit draft.

## Data Flow

- Page state comes from `../../../hooks/admin/usePlaybackProductManagementPage.js`; the card receives
  `product`, `saving`, and the `onSave` / `onToggleEnabled` callbacks.
- The per-row edit draft lives in the CARD, not the hook: a keystroke then re-renders one card rather
  than the whole catalogue, and "Batal" is just discarding local state.

## Rules

- A disabled package renders as `idle`, never `fault`. Red means something is broken; a package the
  operator deliberately stopped selling is not broken (docs/frontend-guide.md).
- The free trial's price control is disabled — the trial path never charges, so a price there would
  be collected and then ignored. The backend rejects it independently.
- There is no delete action. `playback_orders.product_id` references these rows, so removing one
  would orphan the payment history; `enabled = 0` is the removal.

## Verification

- Page + card together: `npm test -- src/pages/PlaybackProductManagement.test.jsx`.
- Backend rules the UI relies on: `cd backend && npm test -- playbackProductAdmin.test.js`.
