## Fase 0 — Hardening darurat produksi (1–2 hari, tanpa deploy kode)

Semua read-only-sudah-diverifikasi; langkah ini murni ops di box. Jalankan lewat skill `ops`.

1. `chmod 600 backend/.env` + seluruh `.env.bak.*`; evaluasi retensi `.env.bak` (arsip terenkripsi atau hapus >7 hari).
2. **Rotasi secrets** `JWT_SECRET`, `CSRF_SECRET`, `API_KEY_SECRET`, `INTERNAL_HOOK_SECRET` — file-file itu world-readable selama berbulan-bulan. Konsekuensi: semua sesi/token lama invalid → jadwalkan jam sepi, umumkan logout massal.
3. Pindahkan kredensial `telegram-bot-api` dari argv ke environment file systemd (`EnvironmentFile=` mode 600).
4. UFW: tutup `:21` (FTP — ganti SFTP/SSH), batasi `:888`/`:36001` (aaPanel) ke IP operator, deny 81–87/8081/3100/3101/3310/3320 bila tidak dipakai publik; MySQL bind `127.0.0.1`.
5. Matikan `cupsd` (tidak relevan di server CCTV).
6. Backup pruning: `find backend/data -name 'cctv.db.*' -mtime +14 -delete` via cron + cap `.env.bak` — atau lebih baik, pindahkan backup ke `backups/` di luar docroot (lihat Fase 5).
7. Deploy `main` (3 commit tertinggal, termasuk fix playback seek/zoom), hapus `backend/tmp_v4.mjs`, catat hash sebelum/sesudah.
8. Paksa ganti password admin yang lemah; aktifkan audit `PASSWORD_MAX_AGE_DAYS`.

**Gate:** `security-audit` skill dijalankan ulang — hasil dicatat sebagai baseline baru.

## Fase 1 — Stabilitas & observability (minggu 1–2)

**Masalah:** box oversubscribed (load 11/8 core) dan restart counter tinggi menutupi apakah restart itu deploy, OOM, atau crash.

1. **Restart forensik**: klasifikasikan 217 restart (deploy-crash vs `max_memory_restart` vs panic). Tambahkan boot marker yang mencatat reason; alert Telegram bila restart >3/jam (edge-triggered, ikuti pola `archiveRouteAlertService`).
2. **Kapasitas**: dokumentasikan alokasi CPU per penghuni box (MediaMTX, motion detectors, backend, recorder, aaPanel). Terapkan `cpu_shares`/`cpuset` untuk `motion.py` (dukungan `cpu_shares` sudah ditambahkan di `f394dca8` — tinggal konfigurasi). Selidiki `BT-Task` aaPanel 31% CPU konstan.
3. **Tuntaskan disiplin logging**: stderr production build masih memuat per-item `went offline`/`thumbnail failed`. Audit semua `console.error/warn` di hot path (`cameraHealthService`, thumbnail) → transisi saja; satu baris ringkasan per sweep.
4. **Health endpoint kaya**: `/api/admin/system-health` menggabungkan pm2 restart rate, loadavg, disk recordings (`/dev/sdb1` 69%), WAL size, antrian recovery, backlog arsip Telegram → satu status ok/warn/critical untuk dashboard + alert (pola `recordingHealthDashboardService` sudah ada — perluas).
5. **Metrik viewer-sisi**: tambahkan counter anonim kegagalan playback (codec fail, fatal HLS, stall) agar "gambar tidak pernah muncul" terlihat tanpa laporan user (`livePictureWatch` sudah deteksi di klien — tinggal telemetri).

## Fase 2 — Security depth (minggu 2–4)

Fondasi akses sudah kuat (audit PASS); ini lapisan berikutnya.

1. **2FA TOTP untuk admin** — ✅ **shipped**: opsional-per-user (`/api/auth/totp/{setup,confirm,disable,status}` + `/totp/verify` challenge) + **wajib untuk role `admin`** via `ADMIN_TOTP_REQUIRED` (default on): admin tanpa 2FA tidak pernah dapat session — password login mengembalikan enroll-token 15 menit (`type=totp_enroll`, fingerprint-bound) yang hanya membuka `/api/auth/totp/{enroll-setup,enroll-confirm}`; confirm mengaktifkan 2FA + mint session atomik; recovery codes hashed, tampil sekali; `disable` ditolak untuk admin selama flag aktif.
2. **Session & token hardening**: inventaris masa berlaku; pertimbangkan rotasi `JWT_SECRET` berkala via key-id (`kid`) agar tidak ada logout massal di masa depan; refresh-token reuse detection (revoke keluarga token bila token lama dipakai ulang).
3. **Dependency & supply chain**: `npm audit` di CI (fail on high/critical), pin versi, Dependabot/Renovate; kebijakan "jangan pakai versi <7 hari" sudah ada di AGENTS.md — otomatisasi.
4. **Header & CSP audit**: CSP ketat untuk SPA (script-src self, media-src untuk blob/HLS), `Referrer-Policy`, review `Permissions-Policy`; pastikan nginx deny rules ter-cover test (tambahkan probe ke `security-audit`).
5. **Rate-limit & brute-force review**: verifikasi limiter benar-benar menghitung di balik Cloudflare/`TRUSTED_PROXY_CIDRS`; honeypot field di form login/register.
6. **Audit trail query UX**: index + tampilan filter di admin untuk `security_audit_log` (sudah dilog — belum tentu mudah dibaca operator).
7. **Secret hygiene test**: guardrail test yang gagal bila pola secret muncul di repo; pre-commit scan (gitleaks).
8. **Rencana sertakan tabel**: probe matrix `security-audit` dijadikan script CI-able (`ops/security-probe.sh`) agar bisa dijalankan kapan saja tanpa konteks.

## Fase 3 — Arsitektur & logic (berkelanjutan, paralel)

Target: kurangi risiko perubahan di file raksasa + naikkan lantai kualitas.

1. **Dekomposisi file frozen** (urutan risiko, satu modul per PR, shrink-don't-grow):
   - `cameraHealthService.js` (3155 ln): probe clients → `health/probes/`, scoring/cadence → `health/scoring`, transition effects → `health/transitions`. Tiru pola recording-domain (facade + policy murni).
   - `cameraService.js` (2809 ln): import/export → `cameraImportService`, read-models → `cameraReadModelService`, bulk area → `areaBulkService`.
   - `hlsProxyService.js` (1587 ln): session store, host policy, response writer → sub-modul.
   - `playbackTokenService.js` (1357 ln): activation, share-text, session-limit, maintenance → sub-modul.
   - Frontend: `VideoPopup.jsx` (1604), `MapView.jsx` (1176), `Playback.jsx` (1160), `MultiViewVideoItem.jsx` (1196) → media state machine + hooks (lihat `docs/frontend-guide.md`).
   - Setelah tiap ekstraksi: **turunkan baseline ratchet** di guardrails agar tidak tumbuh lagi.
2. **State multi-instance-safe**: pm2 `cluster_mode` saat ini hidup hanya karena `instances: 1`. Semua in-memory lock (`cameraAudioLock`, busy-set audio, rate-limit map, access-cache) harus punya fallback DB/file atau cluster mode dikunci ke `fork_mode` + komentar besar. Keputusan dicatat — jangan biarkan jadi bom waktu saat skala naik.
3. **Validasi input terpusat**: `schemaValidators.js` (951 ln) pecah per domain; pertimbangkan adopsi skema deklaratif (Fastify JSON-schema/Ajv sudah built-in) supaya validasi hidup di route, bukan middleware global.
4. **TypeScript bertahap**: mulai dari `utils/` + `policies` murni (`.ts` boleh di samping `.js` via allowJs/build step), lalu services baru wajib TS. Jangan big-bang.
5. **Coverage ratchet**: guardrails punya test-count floor; tambahkan coverage-threshold vitest yang naik-otomatis (baseline sekarang, +1% per bulan — sama filosofi file-size ratchet).
6. **Kontrak API**: endpoint publik diberi contract test (bentuk payload `{success,data}` + field allowlist per role) supaya leak field baru gagal di CI, bukan di audit manual.

## Fase 4 — UI/UX & design system (minggu 3–6)

Fondasi token semantik sudah ada; sekarang naik kelas.

1. **Tuntaskan migrasi token**: ~500 `gray-*` singleton tersisa → selesaikan per-halaman saat disentuh; tiap PR menurunkan baseline guardrail. Zero baru ditegakkan lint.
2. **Aksesibilitas (WCAG 2.2 AA)**: audit keyboard penuh (popup video, map, playback rail), fokus visible, kontras token, `aria-live` untuk status online/offline, reduced-motion. Skill `accessibility` sebagai checklist.
3. **Loading & empty states yang konsisten**: skeleton card standar di `components/ui`, empty-state bergambar + CTA, error-state dengan retry — satu pola di semua surface.
4. **Motion design terukur**: transisi popup/dock/sheet via skill `motion-design` (durasi ≤200ms, easing konsisten, hormati `prefers-reduced-motion`) — micro-interaction di tombol live/favorit.
5. **Performa frontend**: bundle budget di CI (mis. initial ≤250KB gzip, lazy admin chunks — sudah sebagian), `defer` gambar thumbnail (`loading=lazy` + `decoding=async`), preconnect HLS host, audit re-render `CameraContext` saat viewer count update (pakai `useSyncExternalStore`/selector bila perlu).
6. **Mobile-first polish**: semua aturan viewport di skill `ui` tetap hard-rule; tambahkan gesture swipe antar-kamera di popup mobile, bottom-sheet konsisten, PWA install prompt timing.
7. **Dark/light parity test**: screenshot test (Playwright) per halaman utama di kedua mode — bug dark-on-dark jadi merah di CI.
8. **Design tokens v2**: dokumentasikan `components/ui` primitive di Storybook-like page internal (`/admin/ui-kit`, staff-only) supaya pola discoverable tanpa baca kode.

## Fase 5 — Operasional, deploy & data safety (minggu 4–6)

1. **Deploy pipeline resmi**: ikuti `docs/release-channels.md` — tag release, `git checkout <tag>` (bukan detached float), pre-deploy snapshot DB otomatis ke `backups/` (bukan `backend/data/`), post-deploy smoke (boot marker + satu probe `/api/cameras/active`), rollback = checkout tag sebelumnya.
2. **Backup berjenjang**: DB harian → `backups/` (bukan docroot, retensi 14 hari, compress); mingguan → off-box (Telegram backup sudah ada — uji restore-nya!). **Restore drill** per kuartal: restore ke staging, verifikasi tabel kunci.
3. **Log retention**: pm2-logrotate sudah ada; tambahkan rotasi `backend/data/*.log` internal + batasi `.env.bak` (Fase 0).
4. **Runbook insiden**: dari pengalaman nyata repo ini — disk penuh, crash-loop deploy, WAL bloat, Telegram archive stall. Satu halaman per insiden di `ops/` (gejala → diagnosis → mitigasi → permanen).
5. **Multi-box readiness**: dokumentasikan batasan single-box; jika kamera >1500 atau load bertahan >8, pindahkan motion detectors / mediamtx ke node kedua (MediaMTX clustering atau pisah per area).
6. **Konfigurasi sebagai data**: audit semua `process.env` — satu modul config ter-validasi (fail-fast saat boot bila env wajib kosong) menggantikan pembacaan tersebar.

## Fase 6 — Produk & pertumbuhan (opsional, setelah fondasi)

1. **Observability pelanggan rental**: portal `/my` tampilkan uptime kamera, riwayat suspend, bukti tagihan — mengurangi tiket "kamera saya mati?".
2. **Voucher/analytics loop**: konversi voucher → registrasi → subscriber; dashboard funnel.
3. **SEO publik**: `/area/:slug` sudah ada — tambahkan structured data (`VideoObject`/`ItemList`), sitemap per area, OG-image thumbnail per kamera (yang community saja).

5. **Deteksi insiden lalu lintas**: manfaatkan `motion.py`/ronda + `vehicleCountService` → laporan harian per simpang (produk data, bukan hanya video).

## Prinsip eksekusi

- **Satu fase ≠ satu PR.** Tiap butir di atas layak jadi plan/dokumen sendiri di folder ini (lihat konvensi nama `YYYY-MM-DD-<topik>.md`).
- **Urutan wajib**: Fase 0 dulu — secrets yang bocor membuat semua hardening lain percuma.
- **Gate tetap berlaku**: `npm run migrate && npm test` (backend), `npm test && npm run build && npm run lint` (frontend), e2e untuk layout publik, `security-audit` setelah menyentuh access-control.
- **Jangan melanggar invariant** AGENTS.md demi fitur: uang integer, `camera_class` gate, RTSP tidak pernah ke frontend, subscriber footage privat.
- **Produksi read-only** untuk verifikasi; mutasi hanya lewat prosedur deploy.
