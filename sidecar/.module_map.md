# sidecar/.module_map.md

## Why sidecars exist at all

**One repository, separate processes.** A client install must ship everything — that is why these
live in the repo instead of being hand-placed on each box. But they deliberately do NOT run inside
the Fastify backend:

- **Different failure domain.** The archive uploader saturates the uplink for hours at a time
  (measured on prod: ~899 files / 91 GB a day). Inside the backend process it would contend with
  serving HLS. This repo already has that scar: one detached promise rejection once took down every
  live viewer and drove 773 pm2 restarts in 7 hours.
- **Different lifecycle.** The backend restarts on every deploy. A 200 MB upload in flight would be
  killed each time. systemd keeps the uploader alive across application deploys.
- **Different resource profile.** The box is 8-core and the motion detectors already hold ~3.3 of
  them; an isolated unit can be capped without touching the app.

What should NOT stay separate is the *data*. See the note in `tg-archive/README.md`.

## tg-archive/

Uploads finished recording segments to Telegram groups, per camera or per area.

| File | What it is |
|---|---|
| `uploader.py` | The worker (Python). Reads segments, routes them, uploads, records the outcome. |
| `docker-compose.yml` | The **local** Bot API server (`aiogram/telegram-bot-api`) on 127.0.0.1:8092. Local mode is what lifts the 50 MB cloud upload cap to 2000 MB and makes `sendDocument` cost zero CPU — it references the file on disk instead of copying it. |
| `tg-archive.service` | systemd unit. |
| `env.example` | Config template. The real `.env` is gitignored and never leaves the box. |
| `README.md` | Operational detail. |

**Reference points for edits:**
- `send_document()` must pass a `file://` URI — a bare absolute path is parsed as an HTTP URL and
  rejected ("URL host is empty").
- Extra groups use `copyMessage`, never a second upload: Telegram reuses the stored file, so group
  two costs zero extra bandwidth.
- `record()` writes to the sidecar's own `state.db`, which `backend/services/telegramArchiveService.js`
  currently opens **read-only**. That cross-process read is the seam to close next — the uploader
  should write to the application DB so the admin surface reads its own data normally.
